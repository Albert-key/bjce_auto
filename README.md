# bjce-auto-player · 北京干部网络学院自动刷学时

自动完成年度学习任务的视频课程播放：**必修 10 学时 + 选修 40 学时，共 50 学时**。

登录后全自动运行：自动选课 → 自动播放 → 暂停自动续播 → 防"30 分钟无操作"挂机检测 → 播完一章自动切下一章 → 播完一课自动切下一课，达标自动停止。

> ⚠️ **免责声明**：本工具仅供个人学习浏览器自动化技术研究与交流使用。使用者应自行确认符合所在单位及平台的相关规定，因使用本工具产生的一切后果由使用者自行承担。学习是个人的事，技术分享与合规使用并不冲突。

## ✨ 功能特性

| 特性 | 说明 |
|---|---|
| 全自动播放 | 打开课程 → 自动点击播放，无需人工干预 |
| 暂停自动续播 | 每 5 秒轮询播放状态，检测到暂停立即续播 |
| 防挂机检测 | 页面内每 60 秒派发鼠标移动/键盘事件，重置平台"30 分钟无操作自动停止"计时器 |
| 章节自动连播 | 监听播放结束事件，自动点击目录切换下一章 |
| 课程自动切换 | 一门课全部章节播完，自动打开下一门课 |
| 智能选课队列 | 优先播放"我的课程"中未完成的；不足时自动从选课中心按必修/选修补充，播放时自动选课 |
| 完成判定 | 课程播放完毕后**刷新播放页并重新播放 3 秒**（触发服务端进度结算），**进度 ≥ 80% 或平台标记"已学完"，满足其一即完成**（`PROGRESS_PASS` 可调），直接播放下一课 |
| 播放中提前切换 | **播放过程中每分钟检查一次完成条件**（已学完 / 进度 ≥ 80%），满足立即暂停当前课程并播放下一课，不等待播完 |
| 补播提前退出 | 若触发补播，补播期间同样每分钟检查，一旦满足立即停止补播并播放下一课 |
| 自动选课 | 队列无"学习中"课程时自动从选课中心按需补充（必修/选修），无可播课程每 5 分钟重查 |
| 达标即停 | 每播完一课复查年度学时，必修 ≥ 10 且选修 ≥ 40 时自动停止 |
| 自动跳过 | 含考试课程、课程包、外链课程、AICC/文档类课件（非 mp4 视频无法自动播放） |
| 登录态保持 | 浏览器持久化配置，登录一次后续运行免登录；会话失效时自动等待重新登录并继续 |
| 异常自愈 | "正在学习"冲突弹窗自动等待重试；无进展超时自动跳过；错误自动截图到 `errors/` |

## 🚀 快速开始

### 环境要求

- Windows 10/11 x64
- Chrome 或 Edge 浏览器（Windows 一般自带 Edge）

### 方式一：便携版（推荐，无需安装 Python）

下载 Release 中的 ` bjce-auto-player_protable.zip`（约 48 MB），解压到**桌面或文档等可写目录**（不要放进 `C:\Program Files` 等需要管理员权限的目录），双击 **`Start.bat`** 即可。

便携版内置 Python 3.12 嵌入式运行时与全部依赖，开箱即用。自行构建：`python build_portable.py`（首次构建自动下载嵌入式 Python，产物在 `build/` 下）。

### 方式二：源码运行

```bash
git clone https://github.com/<你的用户名>/bjce-auto-player.git
cd bjce-auto-player

# 安装依赖（需要 Python 3.10+）
pip install -r requirements.txt
# 或不使用 pip: python install_libs.py (自动下载 wheel 并解压到 libs/)

# 运行
python auto_play.py
```

### 运行步骤

1. 启动后会弹出浏览器窗口并打开平台首页
2. **首次运行**：在浏览器中手动登录（账号密码/扫码均可），登录后脚本自动接管
3. 之后全自动运行，浏览器窗口可最小化，但**不要关闭**
4. 随时 `Ctrl+C` 停止；达成本年度 50 学时目标后自动停止

## ⚙️ 配置项

`auto_play.py` 顶部可调整：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `TARGET_MUST` | `10.0` | 必修目标学时 |
| `TARGET_SELECT` | `40.0` | 选修目标学时 |
| `PROGRESS_PASS` | `80.0` | 课程进度达到该百分比即视为完成，无需重播 |
| `MUTE_VIDEO` | `True` | 静音播放（不影响学时记录） |
| `SCAN_INTERVAL` | `5` | 播放状态轮询间隔（秒） |
| `MAX_COURSE_MIN` | `240` | 跳过总时长超过该分钟数的课程 |
| `CHUNK_STALL_MIN` | `15` | 单章节无进展超过该分钟数则跳过该课 |

## 🔧 工作原理

基于对平台前端（webpack 打包的 Vue SPA）的逆向分析：

- **播放页**：`#/course/coursePlay?courseID=xxx`。注意 `coursePlay` 是 `/course` 父路由下的**嵌套路由**，直接访问 `#/coursePlay` 会被兜底路由重定向回首页（本项目早期版本踩过的坑）
- **播放器**：xgplayer，页面内 `<video>` 元素直接可控
- **防挂机机制**：平台 `Playcontrol` 组件在 30 分钟无键盘/鼠标操作时弹出 `#alert` 提示并暂停视频；任何 `mousemove`/`keydown` 事件都会重置其计时器 → 脚本每 60 秒在页面内派发合成事件，让计时器永不触发；若仍被暂停则自动点击续播
- **进度上报**：播放页每 5 分钟调用 `userLearningFlow` 接口向服务端上报观看时长（学时由服务端按实际时长累计，脚本始终 1 倍速播放）
- **学时查询**：`api-course/portal/open/personal/getStudyHourDetail?year=当前年` 返回必修/选修已获学时；另有按课程明细累加的备用口径
- **课程队列**：`listMyCourse`（学习中优先）+ 选课中心 `listCourse?searchCourseType=2/1`（2=必修，1=选修）；开始播放时平台自动完成选课
- **登录态**：token 存于 `sessionStorage`（浏览器重启即清空），但脚本启动时平台通过 `getCurrentUser` 接口凭 cookie 自动恢复，正常情况下无需重复登录
- **单会话限制**：平台限制同一账号同时只能有一门课在播放（"正在学习"弹窗），脚本串行播放并在冲突时自动等待重试


## ❓ FAQ

**Q：登录态会丢失吗？**
脚本使用持久化浏览器配置（`profile/`），正常重启电脑后免登录。若在其他浏览器/手机登录同一账号导致会话互踢，脚本会自动回到首页等待重新登录，登录后自动继续，进度不丢失（服务端按心跳累计）。

**Q：为什么提示"正在学习"？**
平台限制单会话。请勿同时在其他窗口/设备播放课程；脚本遇到该提示会自动等待重试。

**Q：需要挂机多久？**
50 学时按 1 倍速约需 30~40 小时实际播放。请在系统电源设置中将"睡眠"设为"从不"，并保持电脑通电联网。运行期间浏览器窗口可最小化。

**Q：会加速播放吗？**
不会。学时由平台服务端按实际观看时长累计，脚本始终 1 倍速，进度达标（80%）即切换下一课，不重复浪费时间。

**Q：杀毒软件报毒？**
本工具仅通过 Playwright 驱动浏览器播放课程，不修改系统。便携版自带 Python 运行时，部分杀软对未签名程序较敏感，添加信任即可。

**Q：如何恢复初始状态？**
删除 `profile/` 目录后重新启动，等同全新环境（需重新登录）。
